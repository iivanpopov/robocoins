# Перехід Robocoins на TanStack Router SPA

Robocoins переходить із TanStack Start на клієнтський застосунок Vite і TanStack Router. Vercel роздає статичну збірку, Roboocode API обслуговує запити, а Sentry продовжує збирати помилки браузера. URL і сценарії входу, реєстрації та роботи в кабінеті зберігаються. Єдина функція, яку прибираємо з екранів, — Feedback.

## Вхід, навігація та завантаження застосунку

`index.html` стає точкою входу Vite, а `src/client.tsx` монтує `RouterProvider` через `createRoot`. У `vite.config.ts` плагін `tanstackRouter` із `@tanstack/router-plugin/vite` стоїть перед React-плагіном: `target: 'react'`, `autoCodeSplitting: true`, маршрути з `src/routes`, ігнорування префікса `-`, генерація в `./generated/routeTree.gen.ts`. Згенероване дерево більше не містить реєстрації TanStack Start. Налаштування Kanjou, UnoCSS, React і `@tanstack/redact` зберігаються.

Один `QueryClient` на екземпляр SPA передається в `QueryClientProvider` і контекст роутера. Маршрутні `beforeLoad` та loaders, кеш запитів, екрани очікування, помилок і 404 та відновлення прокручування працюють у браузері. Сесію визначає запит `GET /api/auth/me`: `401` означає відсутність сесії, інші помилки показуються як помилки завантаження. Зберігаються перевірки ролей, переходи після входу та виходу й винятки для Google callback та відновлення входу. Доступ до даних, як і раніше, контролює Roboocode API. Клієнтський `readCookie` зберігає підтримку чернетки реєстрації, ознаки попередньої реєстрації та налаштування анімацій.

Кореневий маршрут зберігає провайдери локалізації та сповіщень. `index.html` задає `lang="uk"`, viewport, статичний заголовок `Robocoins`, description, спільну іконку й попереднє завантаження шрифтів. Клас `student` і `data-reduced-motion` застосовуються до `document.documentElement`, щоб не змінити оформлення й налаштування анімацій на мобільних і десктопних екранах.

У production індексувати можна лише `/login`, із canonical на чистий `/login` основного домену. Інші маршрути SPA, зокрема `/register`, `/`, Google callback і сторінки кабінету, отримують `X-Robots-Tag: noindex` від Vercel. `robots.txt` має дозволяти пошуковику прочитати цей заголовок. Форма входу рендериться після запуску JavaScript; SSR і пререндер не потрібні. Невідомий URL показує клієнтський екран 404, навіть якщо Vercel повернув `200` зі SPA-оболонкою.

## Запити до Roboocode API

Kubb і Google OAuth зберігають same-origin `/api`; `API_URL` лишається поза браузерною збіркою і використовується для локального проксі та генерації клієнта з OpenAPI.

| Середовище | Маршрутизація                                                                                                                                                                                                                                                                                                          |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vercel     | `vercel.json` збирає застосунок через `bun run build` і публікує `dist`. Зовнішній rewrite `/api/:path*` на `https://<Roboocode-API>/:path*` знімає префікс `/api`; правило стоїть перед fallback на `/index.html`. Fallback обслуговує URL сторінок, пропускаючи `/api`, наявні статичні файли та запити до ресурсів. |
| Локально   | Vite `server.proxy` пересилає `/api` на `API_URL` і так само знімає префікс. Прямі URL сторінок відкриваються через SPA fallback Vite.                                                                                                                                                                                 |

Проксі зберігає метод, тіло, query string, cookies запиту, статус відповіді та `Set-Cookie`. Відповіді `/api` мають `Cache-Control: private, no-store`. Хешовані `/assets/*` зберігають `immutable`. Для `/auth/google/callback` із параметрами й без них Vercel віддає `Referrer-Policy: no-referrer` і `Cache-Control: private, no-store`; `code` і `state` прибираються з браузерного URL за чинним сценарієм.

## Feedback і серверні залежності

Прибираємо кнопки та форми Feedback із головної учня, обох станів магазину, профілю учня та кроку вибору аватара під час реєстрації. Компонент у `src/routes/-components/feedback/`, його стилі, переклади й клієнтську валідацію залишаємо як від’єднану заготовку. Видаляємо `submitFeedback`, виклики серверної мутації та логіку запису й обмеження частоти. Транспорт і симуляцію успішної відправки не додаємо.

Фронтенд більше не має серверного entry point, middleware TanStack Start, SSR-проксі чи доступу до Postgres. Видаляємо `src/server.ts`, `src/start.ts`, `src/lib/proxy.ts`, `src/db/`, `drizzle.config.ts`, команди `db:*` і `DATABASE_URL` з конфігурації фронтенду. `drizzle/` залишається історією міграції, деплой її не запускає. Наявні таблиці та відгуки в БД зберігаються.

| Зміна                        | Пакети                                                                                                                |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Видалити з `dependencies`    | `@tanstack/react-start`, `@tanstack/react-router-ssr-query`, `@sentry/tanstackstart-react`, `drizzle-orm`, `postgres` |
| Видалити з `devDependencies` | `nitro`, `drizzle-kit`                                                                                                |
| Додати до `dependencies`     | `@sentry/react`                                                                                                       |
| Додати до `devDependencies`  | `@tanstack/router-plugin`, `@sentry/bundler-plugins`                                                                  |
| Зберегти                     | `@tanstack/react-router`, `@tanstack/react-query`, `@tanstack/redact`, `dotenv` для Kubb                              |

## Помилки після деплою

`@sentry/react` ініціалізується в браузері до монтування React через `VITE_SENTRY_DSN` із чинною прив’язкою до режиму Vite. Зберігаються автоматичне захоплення необроблених помилок, `defaultOnCatch` роутера й репортинг помилок Query та Mutation. `401` і явно позначені очікувані `4xx` із цих запитів не стають подіями Sentry. Серверні події та логи Start зникають разом із його runtime.

`sentryVitePlugin` із `@sentry/bundler-plugins/vite` стоїть останнім у production-конфігурації. Збірка генерує приховані sourcemaps, завантажує їх за чинними `SENTRY_ORG`, `SENTRY_PROJECT` і `SENTRY_AUTH_TOKEN` та видаляє `.map` із `dist` після завантаження. `SENTRY_AUTH_TOKEN` доступний лише під час збірки. Нові аналітичні події не додаються.

### Перевірка міграції

- Запустити `bun check` і `bun run build`; перевірити, що Vercel публікує `dist` без функцій Start/Nitro, а згенероване дерево маршрутів і lockfile не потребують Start.
- У локальному Vite та на Vercel Preview перевірити реєстрацію, вхід, вихід, відновлення сесії після перезавантаження, Google login/link/unlink, прямі посилання на вкладені сторінки та клієнтський 404. Переконатися, що помилки `/api` і запити до статичних файлів не повертають SPA-оболонку.
- На вузькому й широкому екранах перевірити місця, звідки прибрали Feedback, чернетку реєстрації, оформлення учнівських екранів і налаштування зменшення анімацій. Перевірити заголовки індексації на `/login` та решті маршрутів і заголовки Google callback.
- У збірці з налаштованим Sentry перевірити, що тестова клієнтська помилка має читабельний стек, очікуваний `401` не створює події, а `.map` не роздаються публічно.
