# Перехід Robocoins на Vite+, Node.js 26 і pnpm

Robocoins переходить із Bun на Node.js 26 і pnpm, а окремі Oxlint, Oxfmt і Lefthook замінює локальним `vite-plus`. Розробка, перевірки та збірка працюють без Bun і глобального `vp`. Міграція змінює інструменти розробки та збірки; поведінка застосунку, його оформлення, SEO й аналітика зберігаються.

## Встановлення, розробка та деплой

Фіксуємо Node.js 26 для локальної розробки та `engines.node: "26.x"` для Vercel. Версію pnpm фіксуємо в `packageManager`, а `bun.lock` замінюємо на `pnpm-lock.yaml`. Прибираємо запис про Bun із `mise.toml`. Vercel має встановлювати залежності за тим самим lockfile тією самою версією pnpm, що й локально.

Команди `pnpm dev`, `pnpm build` і `pnpm analyze` запускають локальні `vp dev` та `vp build`; режим `analyze` зберігає звіт про розмір збірки. Vite+ і плагіни мають використовувати один сумісний Vite core: залежність `vite` та її override узгоджені з версією `vite-plus` за [правилами міграції Vite+](https://viteplus.dev/guide/migrate-rules#vite-and-overrides). Локальний запуск і `gen:api:dev` зберігають завантаження `.env.development` без Bun. Те саме стосується локальних `db:*`, доки вони існують.

`vercel.json` запускає збірку через pnpm. Якщо міграція інструментів відбудеться раніше за [перехід на TanStack Router SPA](../01-tanstack-router-spa/spec.md), зберігаємо запуск `db:migrate:ci` перед збіркою. Після переходу на SPA Vercel виконує лише `pnpm build` і публікує `dist` за специфікацією SPA. Для перевірок SPA використовуємо команди з цієї специфікації.

## Перевірки коду та pre-commit

Переносимо правила з `.oxlintrc.json` та `.oxfmtrc.json` до `vite.config.ts`. Зберігаємо React-правила та їхні винятки, одинарні лапки, відсутність крапок з комою, сортування імпортів і виключення `generated/` із форматування та лінтингу. Прибираємо старі конфіги й прямі залежності `oxlint`, `oxfmt`, `oxlint-tsgolint` і `lefthook`. Налаштування Zed використовують той самий конфіг Vite+ для форматування.

| Команда         | Поведінка                                                                                                                                                 |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm check`    | Запускає `vp check` без запису у файли. Увімкнені `typeAware` і `typeCheck` дають перевірку TypeScript через вбудований `tsrs` для застосунку й конфігів. |
| `pnpm fmt`      | Форматує файли через `vp fmt`.                                                                                                                            |
| `pnpm lint`     | Запускає `vp lint`.                                                                                                                                       |
| `pnpm lint:css` | Окремо перевіряє `src/**/*.css` чинними правилами Stylelint.                                                                                              |

Штатний pre-commit Vite+ запускає `vp staged` із `vp check --fix` для файлів, доданих до індексу Git. Виправлення потрапляють до коміту, а незастейджені зміни в тих самих файлах залишаються поза ним. Stylelint запускається лише окремою командою. Новий клон отримує хук під час встановлення залежностей. Команди перевірки описані в `AGENTS.md`.

У наявному клоні після `pnpm install --frozen-lockfile` перевірте `pnpm exec vp hooks status`. Якщо `core.hooksPath` указує на `.vite-hooks/_`, старий `.git/hooks/pre-commit` Lefthook більше не виконується. Якщо залишився інший локальний шлях із власними хуками, перенесіть потрібні перевірки, приберіть цей шлях командою `git config --local --unset core.hooksPath` і виконайте `pnpm exec vp hooks enable`.

### Перевірка міграції

- У чистому клоні без Bun і глобального `vp` виконати `pnpm install --frozen-lockfile`, запустити dev-сервер, генерацію API, збірку та аналіз збірки.
- Запустити `pnpm check` і `pnpm lint:css`. Тимчасова помилка типізації має дати ненульовий код завершення `pnpm check`, а запуск команди не має змінити робочі файли.
- Перевірити pre-commit у новому клоні та після переходу з Lefthook, зокрема на файлі з частково доданими до індексу змінами.
- На Vercel Preview перевірити версії Node.js і pnpm у логах, запуск застосунку та запит через `/api`.
