# «Місія дня»: інтеграція з API

Контракт оновлено командою `bun run gen:api:dev`.

## Реалізовано

- Завантаження місії: `useGetDailyTaskDailyStudentIdDailyTaskGet`.
- Перевірка відповіді та видача нагороди сервером: `useAnswerDailyTaskDailyStudentIdDailyTaskAnswerPost`.
- Серія днів: `useGetStudentStreakStudentStudentIdStreakGet`. Місія та серія завантажуються паралельно в SSR-loader головної й сторінки місії через згенеровані query options. Клієнт використовує той самий кеш без повторного запиту при монтуванні.
- Вибір відповіді з отриманого `options` для `multiple_choice` і `true_false`, текстова відповідь для `text`.
- Завершення визначається серверними `completed_at` і `correct`. Нагорода береться з `reward`, а не обчислюється клієнтом.
- Після успіху оновлюються кеші місії, серії, балансу, профілю, прогресу цілі, історії та сесії; контекст маршрутизатора перечитується.
- Повторне надсилання під час мутації та автоматичні повтори мутації заблоковані. Після невдалої відповіді місія перечитується; остаточне рішення про прийняття наступної спроби залишається за сервером.

## Обмеження поточного контракту

1. Тижневі зірки обчислюються як перетин послідовних днів серії (`start_date`, `days`, за наявності `end_date`) з поточним тижнем. День тижня визначається за серверним `DailyTaskResponse.date`, виконання сьогодні — виключно за `completed_at`. Нульова серія з `null`-датами дає нуль попередніх виконань. Серія не обмежується сімома днями й не обчислюється через `days % 7`. Історії старіших перерваних серій відповідь не містить, тому їхні виконання відновити неможливо.
2. `hotspots` описано як масив довільних словників із числовими або текстовими значеннями. Не визначені координати, одиниці вимірювання, назви властивостей, підписи та спосіб кодування вибраної області в `answer`. Тип `picture` явно позначено недоступним до уточнення контракту.
3. `DailyTaskAnswerResponse` не містить пояснення помилки або дозволу/ліміту повторних спроб. Пояснення не вигадуються; обмеження повторів має контролювати сервер.
4. OpenAPI не описує гарантії ідемпотентності нагороди, правила переривання серії, часовий пояс зміни дня та ліміт 0,7 за сім днів. Це серверні вимоги; клієнт не нараховує монети й не змінює серію через адміністративні мутації.

Для повної реалізації потрібні документований формат областей зображення та відповіді, історія перерваних серій і правила повторних спроб. Після уточнення OpenAPI слід повторно згенерувати API, не редагуючи `generated/` вручну.
