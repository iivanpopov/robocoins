# 06: Назначение преподавателей на группы

**What to build:** Администратор меняет преподавателей конкретной группы и массово назначает преподавателей нескольким группам с понятным результатом каждой операции.

**Blocked by:** 05 — Группы — создание и управление.

**Status:** resolved

- [ ] Выбор преподавателей использует реальный список teacher из API и работает без завершения тикета регистрации преподавателей.
- [ ] Можно назначить до двух преподавателей, заменить состав и снять назначения через доступную мутацию. Передаются user IDs, не ID профилей.
- [ ] Пустой список разрешается интерфейсом, если контракт не требует минимум; серверный запрет отображается корректно.
- [ ] Выбор доступен из деталей/создания группы; после сохранения обновляются детали и затронутые списки. Из преподавательского профиля действие подключается, когда этот профиль реализован.
- [ ] Массовое назначение показывает результат по каждой группе и позволяет повторить однозначно неуспешные записи, не заявляя общей транзакции.
- [ ] Соблюдены мобильный взрослый украинский UI, состояния запросов и 401/403. Выполнен `bun check`; `.test` файлы не создаются.

## Результат интеграции

Принято по ревью diff и интегрировано: `5982815`, `14c8a51` (исходные `bcf8d4663eec6bef5a21405d897dfc44e2cafe50`, `b80601a61e3afb2d4ea143abb2fab1cd3d9d7038`). Повторный `bun check` в integration прошёл с прежними шестью предупреждениями React. Исполнитель повторно проверил build и `bun check` с локально установленными зависимостями после устранения нехватки места в /tmp.

Реальные назначения используют только teacher account user IDs, 0–2 преподавателя, замену и пустой состав. Выбор доступен из создания/деталей группы и профиля преподавателя. Массовый флоу показывает результат каждой группы и повторяет только однозначные отказы; успехи и неизвестные результаты не повторяются. После API подтверждения обновляются связанные group/course/teacher queries. OpenAPI подтверждает maxItems=2 и отсутствие minItems.

Ограничения: authenticated назначения, серверный запрет пустого состава и реальные 401/403/мобильные флоу end-to-end не проверены. Исходный чек-лист не является протоколом браузерных проверок. Работа вне объёма тикета не добавлена.
