# 12: Самостоятельное управление стриком

**What to build:** В профиле ученика администратор просматривает текущий/максимальный стрик и управляет им через доступные серверные операции.

**Blocked by:** 07 — Ученики — список, профиль и регистрация.

**Status:** resolved

- [ ] Текущий и максимальный стрик загружаются через соответствующие API endpoints; отсутствие текущего состояния обрабатывается по фактическому ответу сервера.
- [ ] Запуск, завершение и изменение числа дней выполняются реальными операциями с валидацией неотрицательного количества дней и обновлением показателей после успеха.
- [ ] Доступность действий учитывает известное текущее состояние, но не придумывает отсутствующие в контракте бизнес-правила.
- [ ] Нет связи с расписанием, посещаемостью, моделями занятий и групповыми начислениями. Не создаются журнал и версии стрика в нашей БД.
- [ ] Соблюдены мобильный взрослый украинский UI, загрузка/ошибки, 401/403 и защита повторного submit. Выполнен `bun check`; `.test` файлы не создаются.

Routes/runtime-переводы/types регенерированы по объединённому дереву, сборка и повторный `bun check` в integration прошли с прежними шестью предупреждениями React.

Текущий/максимальный стрик, запуск/завершение/число дней подключены реально. Дни — безопасное целое от 0; действия учитывают известную активность и pending. Локальные формы/диалоги сбрасываются по studentId, ошибки разных mutations не остаются после выбора другой операции. Нет расписания, посещаемости, практики, журнала и таблиц.

Ограничения: authenticated mutations и мобильные флоу не проверены end-to-end. Пробы API для отсутствующего стрика дали 500, а не документированный/ожидаемый 404: 500 честно остаётся ошибкой, отсутствие поддержано для 404/пустого 200 без подмены ошибки нулём. Исходный чек-лист не является протоколом браузерных проверок.
